Case file 001

The confirmation didn’t tell the whole story.

I’m building REPRO around a small idea: instead of telling someone how to reproduce a bug, give them the test that failed.

The example is deliberately small. One click produces Checkout complete on both versions. The older version writes two orders. The fixed version writes one. You only see the difference by checking the database.

01 / Read Inspect the packet

What travels with the bug

The capsule records only what this checkout fixture needs: the actions, the inputs that keep both runs comparable, and the check that distinguishes a failure from a pass. You can inspect the packet without starting the runner.

checkout.repro

Illustrated inventory from the synthetic checkout capsule.

  • manifest.jsonRecipe, capture revision and file digests
  • scenario/events.ndjsonBrowser actions and the final failure marker
  • scenario/assertions.jsonExpected order count and confirmation
  • fixtures/postgres.jsonSynthetic product row
  • fixtures/http.jsonFixed shipping quote response
  • report/capture-summary.jsonObserved counts and check results

02 / Run Replay the fixture

Five actions, one assertion

Restore the synthetic database and replay the main-frame actions in order. The checkout uses the same fixed shipping quote on both runs.

  1. Open the checkout/
  2. Add the productadd-product
  3. Fill the sample labelorder-label
  4. Place the orderplace-order
  5. Wait for confirmationconfirmation

After the fifth action, check the order count. The failure marker is not a browser action.

03 / Check Verify the change

Two saved results

Both runs matched all five recorded actions and showed the same confirmation. The order count is what changed.

Saved evidence from a local run, not a live checkout. The compare command is in the current draft. It does not rerun either report or authenticate its source.

repro compare checkout.repro before.json after.json

04 / Scope Stop at the boundary

What this demo doesn’t do

The included checkout fixture is the only supported target today. Running it locally requires an approved project recipe and runner image. This page just explains the fixture and displays saved evidence.

  • No arbitrary sites, uploads or hosted execution.
  • No captured cookies, screenshots, raw request headers or bodies in the sample.
  • No public installer. The project is still in development.
