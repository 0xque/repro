A bug report you can run

I’m building REPRO around a small idea: instead of telling someone how to reproduce a bug, give them the test that failed.

The example is a checkout that says Checkout complete even though it writes two orders. Same button, same confirmation. The database is where the bug shows up.

How it works

  1. Record the approved synthetic checkout in Chromium.
  2. Review the recording and export the .repro capsule.
  3. Inspect the capsule without Docker.
  4. Replay offline and verify the fix.

The capsule leaves out cookies, screenshots, and raw request data.

Reproducing it isn’t the same as proving it

The browser can tell me that the checkout finished. It can’t tell me that the database wrote exactly one order. That’s why the recorded clicks aren’t the result: the order count is. On the old revision, the same five actions end with two orders. On the fixed revision they end with one. A screenshot of either confirmation would look the same.

The saved reports let a reviewer separate those two questions: did the replay follow the same steps, and did the final check pass? If a run stops matching the recorded actions, that’s a different result from reaching the same checkout and failing the order-count check.

What travels with the report

The capsule keeps the inputs needed for this example: the starting database fixture, the saved shipping response, and the steps and check that tie them together. You can inspect those pieces before deciding to run anything. It doesn’t keep the original browser session, screenshots, or raw requests. It gives you a small test case rather than a recording of everything that happened in a browser.

I’m keeping the example to one synthetic checkout. The two results show what changed for that fixture, not what happens on every checkout, with every account, or in production. The public page shows saved evidence; it doesn’t run a checkout on your behalf.

The included checkout fixture is the only supported target today. No hosted runner, uploads, or public installer.
