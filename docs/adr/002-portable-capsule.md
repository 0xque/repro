# ADR 002 · Byte integrity and runtime compatibility

Write a bounded ZIP containing strict UTF-8 JSON and NDJSON. Hash the exact uncompressed entry bytes with SHA-256. The writer serializes typed objects with `JSON.stringify` and appends one LF. The reader hashes bytes before deserializing and accepts semantically equivalent JSON with different whitespace if its recorded digest matches. The manifest covers the mandatory scenario entries and any declared attachments. The manifest has no self-hash. Hashes detect individual entry changes and provide an oracle identity for comparing reports. A sender who can replace the manifest can change its inventory, so these digests do not identify a trusted publisher.

The recipe contract digest covers the lockfile, TypeScript configuration, Dockerfile and package source bytes. Each variant source digest covers the common app source and the selected variant. The capsule records the contract identity and the bad source digest. To replay, the local runner also checks that the approved image ID carries the local recipe’s contract and source labels. A separately built approved image can be compatible with the capsule when those labels match. Cross-host compatibility has yet to be verified.
